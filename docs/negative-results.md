# 负面结果：试过但失败的方案

> 这部分和协议规格同样重要 —— 它记录了"哪些路已经走死"，能帮后来人省几十小时。
> 目标设备：TCL DSJ-TCLT3A1（`4255:0001`，`Amba Simple Class`）

## 核心症状

```
设备枚举           ✅ 正常
驱动绑定           ✅ 正常（libusb-win32, Service=libusb0, Status=OK）
描述符/字符串读取   ✅ 正常
Bulk OUT 写入       ✅ 成功（16 字节被接受，返回 16）
所有 IN 端点        ❌ 连续 10 秒零字节
端点 GET_STATUS     ✅ 0x0000（未 HALT，硬件正常）
设备屏幕            ✅ 插拔时显示 USB 连接图标
设备录放功能        ✅ 完全正常
```

**结论：USB 控制器活着，端点健康，但固件从不向主机发送数据。**

## 已排除的方案

### 1. 厂商客户端全失败

| 客户端 | 来源 | 结果 |
|---|---|---|
| 警翼 JYManager 3.4.0.1 | 警翼官网 | ❌ 已打补丁绕过 JYA 闸门，仍失败 |
| TCL DSJ-A6 管理软件 | 华军/CSDN | ❌ 32 位版加载 libusb0 后卡死无窗口；64 位版根本不加载 libusb0 |
| **TCL DSJ-T3 管理软件**（型号匹配） | CSDN | ❌ 报「请重新连接」 |
| 恢复宝_JY（专业恢复工具） | 恢复宝 | ❌ 为警翼专用版，且不解决"设备不发言" |

### 2. 密码不是原因

| 密码 | 依据 | 结果 |
|---|---|---|
| `123456` | DSJ-A6 说明书写的初始密码 | 「重新连接」 |
| `000000` | 手册上的初始管理员密码 | 「重新连接」 |
| `15935728` | 用户获取 | 同上 |

**关键判据**：真正的密码错误会报「密码输入错误」；「重新连接」是**通信层**错误。
密码验证需要设备回话，设备不回 → 根本走不到密码判定。

### 3. Ambarella 启动模式（Boot ROM）—— 已验证不是

`GoPro` 的硬砖救援工具 [evilwombat/gopro-usb-tools](https://github.com/evilwombat/gopro-usb-tools)
文档写明：Hero2 进入 USB 命令模式时枚举为 **`4255:0001`**，与目标设备相同。
其 `gp_api.c` 的启动模式协议是**厂商控制传输**（不走 bulk）：

```c
// 读 32 位物理地址
libusb_control_transfer(dev, 0xC0, 0, addr >> 16, addr & 0xFFFF, buf, 4, 1000);
// 写 32 位物理地址
libusb_control_transfer(dev, 0x40, 0, 0, 0, buf12, 12, 1000);
//   buf12 = [00 00 00 30][addr LE][val LE]
```

**实测结果：**

```
请求长度 1/2/4/8/16/64  →  返回长度完全跟随（1/2/4/8/16/64）
wValue/wIndex 任意变化   →  值恒为 0x00000000
8 个内存区域 × 8 个地址  →  非零值 = 0
```

**返回值长度跟随请求、内容全零 = 典型的"未实现请求"桩应答。**

→ **设备不在 Ambarella 启动模式**，`4255:0001` 只是出厂默认 VID/PID。

### 4. 端点组合全部试过

| 写入端点 | 读取端点 | 结果 |
|---|---|---|
| `0x01` (Bulk) | `0x81` (Bulk) | 写成功 / 读超时 |
| `0x01` (Bulk) | `0x82` (Int) | 写成功 / 读超时 |
| `0x02` (Int) | `0x82` (Int) | 写成功 / 读超时 |
| `0x02` (Int) | `0x81` (Bulk) | 写成功 / 读超时 |

### 5. 物理层面

| 尝试 | 结果 |
|---|---|
| 换后置 USB 2.0 口（直连主板） | ❌ 无变化 |
| 物理拔插复位 | ❌ 无变化 |
| `pnputil /restart-device` | ❌ 无变化 |
| 设备关机后插 USB 再开机 | ❌ 屏幕无菜单弹出 |
| 换数据线 | 已排除（能枚举 = D+/D- 正常） |

### 6. 其他

- **libusb0 DLL 版本**：`1.2.3.0` 与 `1.4.0.0` 都试过，枚举行为一致，非版本问题
- **`set_configuration` 补齐**：已按厂商顺序完整调用，无变化
- **超时延长**：轮询 10 秒，无数据

## 结论

**没有任何主机侧软件方案能解决。** 软件能做到"向设备发出请求"，设备不回则无能为力。

## 剩余未验证方向

1. **底部 21 触点底座接口** —— 可能含独立 USB 数据通道或 UART，需拆机测引脚
2. **存储介质形态** —— 电商页写"TF 卡"，但官方手册 42 页图里**无任何卡槽图示**，疑似焊死 eMMC
3. **chip-off / ISP 在板读取** —— 设备能正常录放说明存储芯片完好，成功率高但需专业设备
